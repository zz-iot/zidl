# Ordinary wide-string wire checkpoint

This follows [resolved member IDs](native-cdr-member-ids-slice.md). Ordinary
wide strings now use the XTypes representation in C, C++, Zig and Java: a u32
byte count followed by UTF-16 code units in the selected byte order, without an
inserted BOM or wire terminator. An empty string has byte count zero.

## Runtime and generated paths

The shared native string codec validates even byte counts and the complete
payload span before allocation. It preserves physically unaligned input support
and reports truncation after consuming only the length prefix. Writers check
that twice the unit count fits u32 before writing. Native ordinary and canonical
wide-string writers now share these mechanics; canonical key bytes retain the
correct encoding introduced in the earlier key checkpoint.

The temporary C reference implements the same representation independently.
C-owned reads append a local u16 NUL, so existing `free_wstr` size reconstruction
and allocator contracts remain intact. Interior NUL units remain valid for
native length-bearing values and skip operations; C-owned reads retain their
existing rejection policy and reject before allocating. Empty C-owned values
allocate just their local sentinel. Public reader/writer layouts are unchanged.

Generated C++ writes a byte count and UTF-16 units, and reads halve the validated
byte count without consuming an extra terminator. The whole span is preflighted
before resizing. Its existing UTF-16-unit contract for `std::wstring` is retained,
including on platforms with 32-bit `wchar_t`: values above `UINT16_MAX` are now
rejected instead of silently truncated. Conversion of platform Unicode scalar
values into surrogate pairs remains separate binding work. Explicit UTF-16
surrogate pairs are covered by the fixtures.

Java has distinct wide-string write/read/skip helpers rather than routing wide
values through the narrow UTF-8 codec. Its helpers preflight the complete body,
reject odd byte counts, preserve UTF-16 pairs and do not allocate a String when
skipping. Bounded wide-string reads/writes check UTF-16 unit counts. The sequence-element decoder
uses the same wide path. Generated Java wire methods retain their existing
little-endian contract; split public helpers honor the caller's byte order and
also accept read-only input when reading/skipping.

The sequence witness also fixes native generator allocator-use analysis:
bounded wide elements still need a temporary read allocation, including through
aliases/nested bounded sequences. They must not emit an unused-allocator discard.

## Compatibility

This corrects wire data, not only implementation structure. Prior C/C++/Zig wide
payloads used a unit count plus NUL; Java used its narrow UTF-8 representation.
Regenerate and coordinate affected participants and re-encode persisted wide
payloads. These formats are ambiguous and cannot be reliably auto-detected.
Narrow-string encoding is unchanged. Canonical wide key encoding was already
correct; ordinary payload decode now feeds it the correct language values.

Regenerated C++ code uses the existing additive wide-length helper from the
canonical-key checkpoint, and needs the matching runtime. The C reference stays
the default build; the shared implementation remains opt-in. Java still runs
without a native codec dependency. Production packaging is not switched here.

## Evidence

The [common fixture](../../test/integration/canonical_keys/README.md) now includes
sixteen independently authored wide wire payloads: BMP values, empty values,
UTF-16 pairs, and bounded wide sequences, in XCDR1/XCDR2 and both byte orders.
Native tests and C/C++ consumers compare exact bytes and reject every truncated
prefix. Both Java output modes check their LE payloads, invalid/truncated counts,
collection framing and key hashes. Split helper checks additionally cover BE
read-only input. The sequence also adds an independent canonical key witness,
bringing the common canonical matrix to twenty vectors.

Existing generated boundary tests now use the corrected representation and
verify that malformed wide lengths fail before changing C++ destination storage.
Runtime tests retain both output modes/orders/versions, fixed-buffer failures,
overflow, allocator failure, exact allocation/free sizes and ownership policy.
The independent string samples were updated to the normative representation;
they are not generated by either codec.

Native runtime tests pass all 93 cases. Both C package configurations pass the
68 roundtrip and 30 shared checks (some steps cached). System C/C++ consumers
pass the twenty canonical vectors and all wide-wire witnesses against the
installed staged Debug archive. System C archive consumers also pass Debug and
ReleaseSafe builds. Both Java output modes pass the updated fixture, and all
six native fixture tests pass Zig 0.16. Formatting, whitespace and checkpoint
links pass; zzdds remains unchanged. The full root suite passes 113/113 build
steps and 1,218/1,218 tests, including all 1,126 compiler/backend tests,
independent native/C/C++/Java XCDR known answers and refreshed single/split
golden checks. The existing Debug Maker
workaround remains in use. No performance, other-platform execution or full
zzdds integration claim is made.

Normative reference: [XTypes 1.3 §7.4.1.1.2](https://www.omg.org/spec/DDS-XTypes/1.3/PDF).

Mutable key-only framing follows in the [key-wire checkpoint](native-cdr-key-wire-slice.md).
Remaining key projection shapes, fixed BCD extraction, package placement and the
production build switch remain before consolidation is complete.
